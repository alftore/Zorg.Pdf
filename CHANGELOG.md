# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/). Before 1.0, breaking changes are marked **Breaking**.

## [Unreleased]

### Added

- Repository scaffold: build settings, CI and release workflows, AOT smoke test, and `PdfException` as the base exception type.
- Internal spike (no public API yet): PDF object writer, TrueType parsing, subsetting and embedding, GPOS and `kern` kerning, line breaking and paragraph layout, multi-page flow with tables, "Page X of Y", and PDF/UA-1 tagging that passes veraPDF.
- Linux gate (`scripts/test-linux.sh`) and a CI job: tests with fonts and HarfBuzz required, qpdf, MuPDF, poppler and veraPDF checks.
- Benchmark project comparing the spike invoice with MigraDoc 6.2.4 (MIT).
- The document model: `PdfDocument`, `Heading`, `Paragraph`, `Table` (inline or data-bound rows), `Image` (bytes or data slot), `Spacer`, `PageBreak`, header and footer `PageBand`s, inlines (`TextRun`, `LineBreak`, `Field`), `TextStyle` and `StyleSheet`, and the units `Length`, `Thickness`, `Color`, `PageSize`, `PageSettings`.
- JSON: `PdfDocument.ToJson`, `ParseJson` and `TryParseJson`, source-generated (trim- and AOT-safe), with the JSON Schema in `PdfJsonSchema.Current` and `schema/`. Unknown properties are errors.
- `PdfDocument.Validate` and diagnostics with stable codes and JSON pointers (`docs/diagnostics.md`).
- Example documents in `docs/examples/`, validated by the tests and by an independent JSON Schema validator in the Linux gate.

- Rendering: `PdfDocument.RenderAsync` and `Render` draw headings, paragraphs, spacers and page breaks as tagged PDF, streaming pages as they finish. Headings and `KeepWithNext` blocks stay with the next block's first line. Sync and async renders give the same bytes.
- `RenderOptions` (fonts, `PdfConformance.PdfUA1`, `PdfLimits`, creation date, progress) and `RenderResult`. Fonts come from `FontCollection`, `FontFamily` and `FontSource`; there are no system fonts.
- Checks before writing: no fonts (ZPDF-F001), missing glyphs (F002), unknown families (F004), unreadable fonts (F005) and control characters (T002) stop a render before the first byte. Parts not drawn yet are warnings (R001).
- The Info dictionary and XMP now carry the same title, language, producer and optional dates; the PDF/UA identifier is written only when `PdfUA1` is claimed.

- Fonts: bold, italic and bold-italic faces on `FontFamily`, synthesised (thickened or slanted, ZPDF-F003 Info) when missing; styled text runs (face, size, colour) within a line; fallback families for missing characters; `IFontResolver` and `FontResolvers.System()` as an opt-in; parsed fonts shared across renders.
- A character no font has is now drawn as an empty box with warning ZPDF-F002 (an error under `PdfUA1`), not a failed render.

- Tables: star and fixed columns, a header row that repeats on each page (as an artifact, so it is read once), header fill, rules and cell padding through `TableStyle`, cell alignment, tagged as Table, TR, TH (with column scope) and TD.
- Table rows from data: `RenderOptions.Data = PdfData.Empty.WithRows("lines", rows)`, from `IEnumerable` or `IAsyncEnumerable`, read as the table is laid out. `PdfLimits.MaxTableRows` bounds them.
- Table warnings: a row taller than a page (ZPDF-L001), a data row with the wrong number of cells (L002), fixed columns wider than the page (L003).

- Headers and footers: `PdfDocument.Header` and `Footer` are drawn on every page as pagination artifacts, with room kept for them 12 pt from the content. `Field.PageNumber` and `Field.PageCount` show the real numbers, while pages still stream out as they finish. Built-in `header` and `footer` styles (8 pt). Bands that leave less than 36 pt for the content are an error (ZPDF-L004).

- Images: JPEG embedded as it is, PNG checked row by row and embedded with its own compression when opaque, or decoded with its transparency as a soft mask. Sized from `Width`/`Height` or the pixels at 96 dpi, scaled down to fit, tagged as `Figure` with alt text and a bounding box, or an artifact when `Decorative`. The same image used twice is stored once. Images work in headers and footers too.
- Templates: a document can bind values from a JSON model with `Bind` inlines (`{ "bind": "customer.name", "format": "N2" }`), repeat content per array item with `Repeat` (`{ "type": "repeat", "items": "notes" }`, also as list items) and show content conditionally with `Conditional` (`{ "type": "when", "test": "overdue" }`). The model comes from `PdfData.WithModel`, or from the data JSON that `PdfData.ParseJson` reads. Numbers and dates are formatted in the document's language. Missing values are warnings (ZPDF-B001, B002); incomplete template parts are errors (J023). Text stays literal: there's no `{{ }}` syntax.
- Watermarks: `PdfDocument.Watermark = new Watermark("DRAFT")`, text or an image, with angle, opacity, size, colour, and over or behind the content. One content stream shared by every page, a Pagination/Watermark artifact screen readers skip; text without a size is scaled so its box, turned to the angle, spans most of the page without reaching the edges. Built-in `watermark` style; problems are ZPDF-J022.
- `TextStyle.Language`: text in another language than the document's. A block's style writes `/Lang` on its structure element; a run inside a block is a `Span` with `/Lang`, as PDF/UA asks. Invalid tags are ZPDF-A002. The multilingual example tags each line.
- Zorg.Imaging 0.5.0: page previews no longer depend on an experimental API, so `PdfPreview` isn't marked as one.
- `ImagingProcessor.KeepCmyk`: CMYK photos (JPEG, separated TIFF) keep their inks as DeviceCMYK, shrunk and turned through Zorg.Imaging 0.5's `DecodeCmyk`, for print; an untouched CMYK JPEG goes in as it is. Not for PDF/A.
- Fixed: `ImagingProcessor` left a CMYK JPEG without a colour profile to Zorg.Pdf, which embeds it as DeviceCMYK; it now converts it to sRGB as documented, so such photos work under PDF/A.
- Norwegian window letters: `TextBoxPreset.NorwegianWindow` (JSON `"norwegianWindow"`) places the address for a C5/E65 window envelope with the A4 sheet folded in three, at 21.27 mm (the first tab of the grid common in Norwegian business letters) from 40 mm down, and checks Posten's rules for machine-read addresses: two lines or more without blank lines (ZPDF-L008) and one plain font from Posten's list (ZPDF-L009). A new example, `docs/examples/brev.json`, is a Norwegian offer letter with a reference block and a footer with organisation number and account. It doesn't claim conformance with NS 4129, whose text we haven't seen.
- Factur-X and ZUGFeRD: a new package, `Zorg.Pdf.Invoicing`. `FacturX.Read(xml)` reads the CII XML an invoicing system writes (DTDs and external resources off) and its profile (MINIMUM, BASIC WL, BASIC, EN 16931, EXTENDED, XRECHNUNG); `ApplyTo(document)` embeds it as `factur-x.xml` (`xrechnung.xml`) with the relationship receivers expect, and `ApplyTo(options)` adds the `fx:` metadata with its PDF/A extension schema and claims PDF/A-3 (3b at least). ZPDF-X001 to X003 refuse XML that isn't CII or names no known profile. `zorg-pdf render --facturx invoice.xml`. Core gained `RenderOptions.MetadataSchemas` (`XmpSchema`, `XmpProperty`) for extra XMP metadata, described in the PDF/A extension schema (ZPDF-R005), and `RenderOptions` is now a record, so `options with { ... }` copies it; the agent tools now pass on every render option the host sets (the hyphenator was dropped before).
- Attachments and PDF/A-3: `PdfDocument.Attachments` (JSON `"attachments"`) carries files in the PDF, such as an e-invoice's XML: each an embedded file with its media type, size, MD5 checksum, description and relationship (`AttachmentRelationship`), listed in the attachments panel and, as PDF/A-3 requires, among the document's associated files. `PdfArchive.PdfA3a`, `PdfA3u` and `PdfA3b` claim PDF/A-3 (`--pdfa 3a`); attachments under PDF/A-2 are an error (ZPDF-A005). `PdfData.WithFile` and `zorg-pdf --file slot=path` supply them; `PdfLimits.MaxAttachmentBytes` bounds them (ZPDF-R004); ZPDF-J031 checks names and media types. Checked with veraPDF (PDF/A-3a, PDF/UA-1) and qpdf.
- Merging, extracting, splitting and new metadata: `PdfFiles.MergeAsync([new PdfPageSource(a), new PdfPageSource(b) { Pages = "2-4" }], output, new PdfFileOptions { Title = "Pack" })` and `ExtractAsync(file, "1-3,5", output)` copy pages of any PDFs into a new file, deterministically. Inherited page attributes are made explicit; links between copied pages are kept (named destinations made explicit), links to pages left out and actions that run scripts or open files are dropped. Tags, bookmarks and form logic aren't kept, and the result says so (ZPDF-E001 to E004). `zorg-pdf merge a.pdf b.pdf:2-4 -o out.pdf`, `extract in.pdf --pages 1-3 -o out.pdf` and `split in.pdf`, with `--title`, `--author`, `--subject`, `--keywords` and `--lang`.
- Letterhead and stationery: `PdfDocument.Background = new PageBackground(ImageSource.FromSlot("letterhead")) { FirstPage = 1, OtherPages = 2 }` (JSON `"background"`) draws a page of an existing PDF behind the first page and another behind the rest, vector and sharp. Each page used is copied once as a form XObject, without the letterhead's own tags, optional content or metadata, and drawn first on each page as a layout artifact. A page of another size is scaled to fit and centred (ZPDF-G003); a rotated page is turned as viewers show it. Under PDF/UA or PDF/A a font that isn't embedded is an error (ZPDF-G004), and under PDF/A so is CMYK colour (ZPDF-G005); files that can't be used stop the render before anything is written (ZPDF-G001, G002, J030). `PdfData.WithPdf` supplies the file; `zorg-pdf --image letterhead=file.pdf` too. Previews draw form XObjects.
- Reading existing PDFs: `PdfFileInfo.Read` and `ReadAsync` give any PDF's pages (visible size and rotation), metadata, language, and whether it's tagged or encrypted. Cross-reference tables and streams, incremental updates, object streams and the Flate, LZW, ASCIIHex, ASCII85 and RunLength filters are read; a damaged file is read the way viewers read it (objects found by scanning, wrong stream lengths, cut-off compressed data), with diagnostics ZPDF-P001 to P004. `PdfReadLimits` bounds file size, objects, decoded bytes and pages, and every failure is a `PdfReadException`. An in-repo fuzzer runs on every test run, and the Linux gate checks page counts against qpdf over seven rewrites of every smoke PDF. `zorg-pdf info file.pdf` (with `--json`) shows the same.
- Fixed: Markdown nested past Markdig's depth limit crashed the CLI; it's now ZPDF-M004. A section's `startAt` is capped (260 for letters), so labels stay short. Link URIs with international host names are written as punycode. A table of contents makes room for long labels (prefixes, roman numerals). A section break as the last block no longer adds a blank page.
- Markdown: a new package, `Zorg.Pdf.Markdown`, turns CommonMark and GitHub-flavoured Markdown into a document with Markdig (`MarkdownDocument.Parse`): headings, bold and italic, hard breaks, lists (numbered from their start, nested, task boxes as `[x]`), pipe tables with alignment, code blocks (built-in `code` style), quotes (`quote` style), rules, images on a line of their own (a data slot named by the path, alt text from the description) and links (`https`, `http`, `mailto`, `#id`). YAML front matter sets `title` and `lang`, else the first level 1 heading is the title. Raw HTML is left out with ZPDF-M001; ZPDF-M002 and M003 note what was simplified. `zorg-pdf render notes.md` reads images from beside the file (never from outside its folder). `PdfToolOptions.ParseMarkdown` adds a `render_markdown` agent tool. `DocumentParseResult` has a public constructor.
- Hyphenation: `TextStyle.Hyphens` (`Manual`, the default: soft hyphens only; `Auto`; `None`) and `RenderOptions.Hyphenator` (`IHyphenator`). Only a word that overflows a line is hyphenated; headings stay `Manual`. A hyphen added at a line end is marked `/ActualText` U+00AD, so it copies out as a soft hyphen (checked with pdftotext and veraPDF). A new package, `Zorg.Pdf.Hyphenation`, has `PatternHyphenator.Default` with Liang's patterns from hyph-utf8, shipped unchanged: English (US, UK), German (1996), French, Norwegian (bokmål, nynorsk) and Danish. The CLI uses it; the letter example hyphenates. ZPDF-T003 notes text set to hyphenate that can't be.
- Per-section headers and footers: `SectionBreak.Header` and `Footer` (null keeps the section before's, `PageBand.None` removes it), so a cover page goes without a footer and an appendix gets its own header. Every section's bands are measured before the first page, each section has its own content area, and a band without fields is one stream per section. The new handbook example has a cover, roman front matter with a table of contents, a numbered body and an A-numbered appendix.
- Sections and page labels: `PdfDocument.Numbering` and `SectionBreak` (`Numbering`, `StartAt`, `Prefix`) number pages 1, i, I, a or A, restarted or prefixed per section (roman front matter, A-1 for an appendix). The numbers are written as `/PageLabels` for the viewer's page box and shown by page number fields and tables of contents; `PageCount` stays the total. A break on a fresh page adds no blank page. Problems are ZPDF-J029.
- Tables of contents: `new TableOfContents { Title = "Contents", MaxLevel = 2 }` (JSON `"type": "tableOfContents"`) lists the top-level headings after it with dot leaders and page numbers, each entry a link to its heading, tagged TOC, TOCI and Link. Laid out in one pass where it stands; the numbers are drawn into a second stream of its pages when the document finishes. Styles `toc1` (bold) to `toc6`. Problems are ZPDF-J028. The report example has one.
- Links: `new Link(["our terms"]) { Target = "https://..." }` (or `mailto:`, or `#id` to a block), in JSON `{ "link": "...", "inlines": [...], "description": "..." }`, in headings, paragraphs and list items. Drawn in the built-in `link` style; one annotation per link per page with an area per line, `/Contents` from the description or text, and tagged as a Link element holding its text and an OBJR, as PDF/UA asks. Parent-tree keys cover pages and annotations. Problems are ZPDF-J027. The letter example has web and e-mail links, checked by veraPDF.
- Bookmarks: headings of level 1 to `PdfDocument.OutlineLevels` (3 by default, 0 for none) become the viewer's outline, nested by level and opened at the heading. `Block.Id` names a top-level block as a named destination (`file.pdf#appendix-b`), sorted by name. Problems are ZPDF-J025 (ids) and J026.
- PDF/A-2: `RenderOptions.Archive = PdfArchive.PdfA2b`, `PdfA2u` or `PdfA2a` writes an sRGB output intent (the ICC's `sRGB2014.icc`, embedded unchanged) and the PDF/A identifier in XMP, declaring PDF/UA's identifier as an extension schema when both are claimed. CMYK images (ZPDF-I001) and missing characters (F002) stop an archive render; 2a also stops on skipped heading levels. `zorg-pdf --pdfa 2a`. Every example passes veraPDF's PDF/A-2a and PDF/UA-1 checks in the Linux gate.
- TrueType collections (`.ttc`): `FontSource.FromFile(path, face)` and `FromBytes(bytes, face)` pick a face, copied out and embedded like a `.ttf`; `FontCollection.FromFolder`, installed fonts and `zorg-pdf --font` find every TrueType face of a collection by its family. Many system fonts (Cambria, Yu Gothic, MS Gothic, Noto CJK as TTC) become usable.
- Groundwork for 0.3: path operators in the content writer (curves, close, clip, dashes, caps and joins) and parent-tree keys shared by pages and annotations; previews draw fill-and-stroke and accept caps, joins and dashes.
- `ImagingProcessor` uses Zorg.Imaging 0.4: images are read without a copy, JPEGs larger than they're printed decode at reduced size, 16-bit and BGRA images are converted instead of decoded twice, and an alpha channel no pixel uses gets no soft mask.
- Page previews: `PdfPreview` in `Zorg.Pdf.Imaging` draws pages of PDFs that Zorg.Pdf wrote as PNG through Zorg.Imaging 0.4's canvas (text from the embedded fonts, rules and fills, images with soft masks, watermark opacity), the same on every machine, with limits for hostile files. It refuses PDFs it didn't write. The CLI has `zorg-pdf preview`, and `render --preview` and `watch --preview`. The agent tools gain `render_preview` (a page as an image, when the host sets `PdfToolOptions.PreviewAsync`) and `get_capabilities`. The Linux gate compares every example's preview with MuPDF's.
- Text boxes: `TextBox` puts paragraphs at a fixed place on the page, measured from the paper's corner, without taking room in the flow: a letter's address for a window envelope (`Preset = TextBoxPreset.Din5008A` or `Din5008B`), reference blocks, form fields. Text too long is made smaller in 0.25 pt steps down to `MinSize` (Info ZPDF-L005), or with `Overflow = Clip` cut at a whole line (warning L006); `Visible` draws past the box. Optional padding and border; tagged as a Div of Ps. Problems are J024 and L007. The letter example's address is one.
- Row templates: `TableRows.Repeat("lines", cells)`, in JSON `"rows": { "repeat": "lines", "cells": [...] }`, make one table row per object of a model array, with `@number` and outer values in scope. Cells take a binding shorthand, `{ "bind": "amount", "format": "N2" }`, and a `Cell(inlines)` constructor. The reminder example's invoice table is one.
- The `zorg-pdf` command-line tool (package `Zorg.Pdf.Tool`): `render`, `validate`, `watch` and `schema`. Problems print as `file:/pointer: error CODE: message` or as JSON (`--json`); fonts from `--fonts <folder>`, `--font <file>` or the installed ones; images from `--image slot=file`; documents from standard input and PDFs to standard output with `-`. Exit codes 0, 1 (problems) and 2 (command line or files).
- `FontCollection.FromFiles` and `FromFolder` group TrueType files into families by the names inside them, taking the weight nearest regular and bold; `AddRange` merges collections.
- Tables: a row taller than a page splits across pages line by line, under the repeated header, and stays one tagged row; rows that fit still move whole. Cells span columns and rows (`ColumnSpan`, `RowSpan`; JSON `columnSpan`, `rowSpan`), tagged with ColSpan and RowSpan, with rules that stop at spanning cells. Rows joined by a row span stay on one page. ZPDF-J012 and L002 count spans; L001 now only reports spanned rows taller than a page.
- Lists: `new List(["One", "Two"]) { Marker = ListMarker.Number }`, in JSON `{ "type": "list", "items": [...] }`. Bullets, numbers, letters and Roman numerals, a start number, nesting up to six deep, and items of paragraphs and nested lists. Tagged L, LI, Lbl and LBody with a ListNumbering attribute, as PDF/UA asks; items flow over pages and a marker stays with its first line. Problems are ZPDF-J020 and J021.
- `Zorg.Pdf.Imaging`: `ImagingProcessor`, built on Zorg.Imaging, reads WebP, GIF, BMP and TIFF, applies EXIF orientation, converts CMYK and ICC-profiled images to sRGB, and shrinks images to the resolution they're printed at (300 dpi by default), drawn at their original size. JPEG and PNG that need none of that are embedded untouched.
- `RenderOptions.ImageProcessor` (`IImageProcessor`): prepares each image before it's embedded, from its bytes and the largest box it's drawn in, returning JPEG to pass through or pixels (grey, RGB or CMYK, with optional alpha) for Zorg.Pdf to compress. Other formats, orientation, colour conversion and shrinking go there; `Zorg.Pdf.Imaging` will provide one built on Zorg.Imaging. Without one, JPEG and PNG are read as before.
- `Zorg.Pdf.Extensions.AI`: the agent tools `get_document_schema`, `validate_document` and `render_document` as `Microsoft.Extensions.AI` functions, AOT-safe. The host supplies fonts, conformance, limits and storage; the model supplies the document and its data as JSON.
- `PdfData.ParseJson` reads render data from JSON: table rows as arrays of cells, images as `{ "base64": ... }`.
- A heading that skips a level is a warning (ZPDF-A004), and an error under `PdfUA1`.
- Ten example documents in `docs/examples`, with data in `docs/examples/data`. Every one renders under `PdfUA1`, passes veraPDF in the Linux gate, and is hashed on Windows and Linux in CI.
- Smaller files: objects other than streams go into compressed object streams, and the file ends with a compressed cross-reference stream (PDF 1.5). A tagged 1,000-row invoice went from 820 KB to 218 KB.
- `PdfData.WithImage` supplies an image slot's bytes, or loads them asynchronously before the first page. `PdfLimits.MaxImageBytes` (50 MB) and `MaxImagePixels` (50 million) bound what a render accepts. A damaged or unsupported image (ZPDF-I001) or one over the limits (I002) stops the render before anything is written.

### Removed

- The spike (`Spike/`), replaced by the public render API.

### Fixed

- A GPOS extension lookup offset above `int.MaxValue` threw `OverflowException` instead of `PdfException`.
